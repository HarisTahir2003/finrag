# Dependencies for a hosted Streamlit deployment (Streamlit Community Cloud and
# anything else that installs a requirements file rather than building an image).
#
# This file previously held `-e .[local,google,semantic,app,dev]` as a
# convenience for local installs. Streamlit Community Cloud requires a
# requirements.txt at the repository root and installs exactly what it finds
# there, so the name had to go to the deployment set. For a development
# environment use pyproject.toml directly, which is the source of truth either
# way:
#
#     pip install -e ".[local,google,semantic,app,dev]"
#
# tests/test_requirements.py asserts this file has not drifted from the
# base dependencies plus the [local], [app] and [groq] extras.
#
# ---------------------------------------------------------------------------
# CPU-only torch, pinned by URL, and this line is the whole reason the build
# succeeds. `pip install torch` on Linux fetches a 527MB wheel that declares
# fifteen nvidia-* packages plus triton -- gigabytes of CUDA, on a free tier
# with two cores and no GPU. It is the single most common way a build like this
# dies. The +cpu wheel is 183MB and declares none of them.
#
# The URL is cp312-specific by construction. If the host runs a different
# Python the install fails loudly with "not a supported wheel on this platform",
# which is a clear error with an obvious fix, not a silent one.
https://download.pytorch.org/whl/cpu/torch-2.13.0%2Bcpu-cp312-cp312-manylinux_2_28_x86_64.whl
